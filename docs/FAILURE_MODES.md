# RosterGuard Failure Modes & Mitigation Matrix

Authoritative engineering analysis of failure scenarios, boundary conditions, and self-healing mechanisms.

| # | Failure Scenario | Trigger / Root Cause | Detection Mechanism | Recovery / Mitigation | Expected Behavior | Automated Test Proof |
|---|---|---|---|---|---|---|
| **F1** | **Out-of-Order HR Events** | Async message bus or network lag delivers version $N-1$ after version $N$ was already applied. | PostgreSQL conditional update check: `WHERE employee.source_version < EXCLUDED.source_version`. | Query returns 0 rows updated; service detects stored version > incoming version. | Discarded as stale (`409 STALE`). Version monotonicity strictly preserved. | `EmployeeConcurrencyIT` |
| **F2** | **Duplicate Event Delivery** | Upstream HR system retries on timeout, sending identical event payload twice. | Comparison of incoming payload SHA-256 hash against stored `payload_hash` at identical `source_version`. | Idempotent short-circuit; database is untouched. | Returns `200 DUPLICATE` with zero state changes or duplicate outbox events. | `EmployeeSyncServiceIT`, `OutboxMutationsIT` |
| **F3** | **Split-Brain / Same-Version Conflict** | HR system issues two contradictory events with identical version but different profiles. | Incoming payload SHA-256 hash does not match stored `payload_hash` at identical `source_version`. | Stored row left unchanged; conflicting payload persisted in `employee_event_review` (`status = 'PENDING'`). | Returns `200 CONFLICT_HELD`. Human operator notified to resolve dispute. | `EmployeeSyncServiceIT` |
| **F4** | **Corrupted / Partial CSV Snapshot** | Network drops or truncated export omits 50% of active employees from CSV. | `activeCountAtStart > 0` and missing ratio $\ge$ configured threshold (`rosterguard.roster.missing-threshold`, default 30%). | Deactivations are suspended; upserts applied safely; status set to `AWAITING_APPROVAL`. | Zero active employees deactivated; zero bookings or seats cancelled without operator sign-off. | `RosterImportSafetyGatesIT` |
| **F5** | **Malformed CSV Rows** | Syntax error, unparseable date, or invalid email/phone format in individual CSV lines. | Regex and format validation during streaming parse. | Field error logged in `import_row_error` (without raw PII). If ID is parseable, stored in `import_seen_id`. | Valid rows proceed to staging; parseable employee IDs protected from missing deactivation. | `LargeFileResilienceTest` |
| **F6** | **Duplicate IDs in CSV Snapshot** | Upstream export error generates duplicate records for the same employee in one file. | Aggregation count in `import_seen_id` where `occurrences > 1`. | Reconciliation halts immediately; status set to `NEEDS_REVIEW` (`HoldReason.DUPLICATE_EMPLOYEE_ID`). | Entire import held; zero destructive updates or deactivations applied. | `LargeFileResilienceTest` |
| **F7** | **Stale CSV Snapshot Watermark** | An older CSV snapshot is uploaded after real-time events or a newer snapshot was processed. | Check `snapshotGeneratedAt <= tenant.latest_snapshot_watermark` and row check `source_updated_at <= snapshotGeneratedAt`. | Import held in `NEEDS_REVIEW` (`HoldReason.STALE_SNAPSHOT`). Upsert version guard prevents regression. | Stale file rejected; current database state untouched. | `RosterImportSafetyGatesIT` |
| **F8** | **Partial Failure During Mutation** | DB connection drops or constraint violation occurs while cancelling bookings or writing outbox. | Uncaught exception within active Spring transaction boundary. | Spring `@Transactional` rolls back employee mutation, booking cancellations, seat releases, and outbox insert. | Database remains completely consistent; zero orphaned seats or dangling outbox records. | `OutboxMutationsIT`, `DeactivationTransactionRollbackIT` |
| **F9** | **Worker Crash During Outbox Publish** | Outbox worker claims event and delivers to external broker, but JVM crashes before writing `PUBLISHED`. | Atomic CTE lease expires after configured lease duration (default 60 seconds). | Surviving worker re-claims event via `FOR UPDATE SKIP LOCKED`. | Delivered **at least once**; downstream consumers deduplicate by `id` or `dedup_key`. | `OutboxRelayIT` |
| **F10** | **Repeated Downstream Broker Outage** | External message broker or notification service unreachable. | Outbox worker catches publishing exceptions. | Exponential backoff (`base * 2^attempts`); transitions to `FAILED` (Dead Letter Queue) after 5 attempts. | Queue head-of-line blocking avoided; failed events isolated for operator triage. | `OutboxRelayIT` |
| **F11** | **Approval / Rejection Race** | Two operators concurrently attempt to approve or reject the same held import. | Atomic status transition: `UPDATE roster_import SET status = 'COMPLETED' WHERE ... AND status = 'AWAITING_APPROVAL'`. | Exactly one transaction achieves update count = 1; the other receives 0 rows and returns empty. | Exactly one operator decision takes effect; deactivations cannot run twice. | `RosterImportSafetyGatesIT` |
| **F12** | **Invalid CSV Header Row** | Header contains missing required columns, duplicate column names, or unexpected columns. | Header validation contract check at row 0. | Emits row 0 error in `import_row_error` and halts parsing immediately. Status set to `NEEDS_REVIEW`. | Zero data rows staged; file rejected safely without data corruption. | `CsvParserTest` |
| **F13** | **Cross-Tenant Data Tampering** | Attacker injects foreign tenant employee ID or queries another tenant's outbox. | Mandatory JWT `tenant` claim validation; composite primary/foreign keys leading with `tenant_id`. | Query planner enforces tenant isolation at engine level. | Access denied (`403 Forbidden` or `404 Not Found`). Cross-tenant leakage impossible. | `TenantScopingSchemaIT`, `SecurityIT`, `RosterImportErrorApiIT` |
| **F14** | **Massive CSV Heap Exhaustion (OOM)** | Large enterprise uploads 200,000+ row CSV (~18+ MB text). | Stream-based `BufferedReader` parsing in batches of 1,000 flushed to PostgreSQL staging. | $O(1)$ memory consumption; peak heap capped at 113 MB (well under 256 MB cap). | Fast streaming ingestion (29.07s for 200k rows) with flat memory footprint. | `CsvReconciliationBenchmark` |
